# テスト設計・実装方針

AI PFC Menu Generator では、**Vitest** と **React Testing Library** を用いてテストを実装しています。

---

## 1. テスト環境・技術スタック

*   **テストランナー**: Vitest (`vitest`)
*   **DOM シミュレーション**: `happy-dom` (CLIでの高速なDOM操作用)
*   **UI テスト**: `@testing-library/react` (Reactコンポーネントのテスト)
*   **アサーション**: `@testing-library/jest-dom` (DOM固有のマッチャーを提供)

---

## 2. ディレクトリ構成

テストファイルは `src/` 配下の各コンポーネントのすぐ近く、もしくは `src/__tests__/` ディレクトリに集約して配置する方針を取っています。
現在、主要なテストは `src/__tests__/` ディレクトリに配置されています。

```
src/
 └─ __tests__/
     ├─ components/     # (必要に応じて) UIコンポーネントのテスト
     ├─ setup.ts        # Vitest / jest-dom の初期設定ファイル
     ├─ *.test.tsx      # Reactコンポーネントのテスト
     └─ *.test.ts       # ロジック・ユーティリティのテスト
```

---

## 3. テストの対象範囲

### 3.1. UIコンポーネントのテスト (`.test.tsx`)

React Testing Library を用いて、**ユーザーの視点**に立ったテストを記述します。
主に以下の点を検証します。

*   **レンダリング**: 適切な初期状態（デフォルト値、ローディング表示など）でレンダリングされるか。
*   **ユーザーインタラクション**: ボタンクリック、フォーム入力に対して正しく状態が更新され、UIが変化するか。
*   **エラーハンドリング**: 不正な入力（PFC合計が100%以外、カロリー超過など）をした際に、エラーメッセージが正しく表示されるか。

**主なテストファイル例:**
*   `InputForm.calorie.test.tsx`: カロリー入力・PFC比率計算・各種バリデーションの振る舞い。
*   `MenuDisplay.test.tsx`: 生成された献立（JSON）が正しくリストやテーブルとして描画されるか。

### 3.2. ロジック・ユーティリティのテスト (`.test.ts`)

APIルートで使用されるバックエンドのロジックや、データ変換・バリデーション関数など、UIに依存しない純粋な関数のテストです。

*   **バリデーション**: Zodスキーマ（`validation.ts`）を用いた境界値チェックや不正フォーマットの弾きなど。
*   **サニタイズ**: `sanitizeUserInput` のようなインジェクション対策処理が、悪意ある文字列を想定通りに除去できるか。
*   **APIエッジケース**: レートリミット（429）やプロンプト過多などでのリトライ・エラーハンドリング（`retry.test.ts`、`route-logic.test.ts`配下のモックテスト等）。

---

## 4. テストコマンドの実行方法

`package.json` に定義された npm スクリプトを使用してテストを実行します。

| コマンド | 説明 |
|---|---|
| `npm run test` | Vitest を**ウォッチモード**で起動します。ファイル変更時に自動でテストが再実行されるため、開発中に便利です。 |
| `npm run test:ci` | 1回だけテストを実行して終了します。CI/CDパイプラインや、プッシュ前の全体確認で使用します。 |

### 実行例（CLI）

```bash
# ローカル開発時のウォッチモード起動
npm run test

# CI向け実行
npm run test:ci
```

---

## 5. モック化（Mocking）の方針

外部API（Gemini API、Supabase等）や、ブラウザ固有API（`window.localStorage`、`fetch`等）に依存するロジックをテストする場合は、Vitest のモック機能 (`vi.mock()`, `vi.fn()`) を活用します。

*   **Gemini API**: 実際のAPIリクエストは行わず、モックレスポンスを返却させて内部ロジックの挙動を検証します。
*   **Upstash RateLimit**: レート制限に引っかかった場合・通過した場合のモックを切り替えてテストします。
