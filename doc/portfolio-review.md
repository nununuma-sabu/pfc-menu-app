# ポートフォリオ評価レポート（2026-02）

## 総評（先に結論）

**現時点で「個人開発としては十分強い」構成です。**

特に、以下が評価ポイントです。

- 「課題起点」でプロダクトを作っている（Whyが明確）
- AI機能を載せるだけでなく、**入力バリデーション・サニタイズ・レート制限**など非機能要件を実装している
- テストが存在し、技術ドキュメント（validation/security）を整備している

転職ポートフォリオとしては既に戦える品質です。  
一方で、**マネタイズ**を目指すなら、今後は「機能」よりも

1. 継続利用の仕組み（習慣化）
2. 課金導線（誰が、何に、いくら払うか）
3. 信頼性（栄養値の妥当性・再現性）

を優先すると伸びやすいです。

## 現状の強み（ポートフォリオ観点）

### 1) ストーリーが強い（課題→実装）

READMEに「なぜ作ったか」が書かれており、
「個人の痛みをプロダクトで解いた」流れが明確です。

### 2) 機能の粒度が実用的

PFCプリセット、TDEE計算、除外食材、固定レシピなど、
単発デモではなく「実際に使う機能」が揃っています。

### 3) セキュリティ配慮が説明可能

- System Instruction分離
- 入力サニタイズ
- Structured Output
- レート制限

まで言語化できているため、面接や営業時の説明力が高いです。

### 4) テスト・ドキュメントがある

`__tests__`配下のテストと `doc/*.md` の設計書は、
「作って終わり」ではない運用意識の証明になります。

## マネタイズ視点での改善優先度（高→低）

## P0（最優先）: 誰が課金するかを明確化

最低でも以下のどれかに絞ると良いです。

- ダイエット初心者（迷わず食事を決めたい）
- 筋トレ中級者（PFC管理を自動化したい）
- 忙しい会社員（意思決定コスト削減）

**推奨アクション**

- LPに「対象ユーザー」を明記
- 料金ページに「無料でできること / 有料で得られる成果」を明記

## P1: 無料→有料の境界を設計

例：

- 無料：1日1回、3食、履歴3件まで
- 有料（¥500〜¥980/月）：
  - 生成回数上限の緩和
  - 1週間分の一括献立
  - 買い物リスト自動最適化
  - お気に入り・履歴の無制限保存

## P1: 継続率を上げる機能（LTV改善）

- 週間計画・達成率表示
- 体重/体脂肪ログ連携
- 「先週比」の可視化

単発の「生成体験」から、
継続の「習慣化ツール」へ寄せると解約率が下がります。

## P2: 信頼性を高める

AI出力の栄養値に対して、最小限でも以下を実施。

- 上限/下限のサニティチェック
- 異常値時の再生成
- 免責と注意事項（医療助言ではない）

将来的にB2Bや提携を狙う場合、ここが効きます。
